Supportal AI Agent — User Workflow

Step-by-step guide: setup → authentication → data ingestion → analysis · v1.4.0

1
Initial Setup — one time
Start both servers and configure your connection profile
1
Start NiceGUI
In your terminal:
cd ~/Downloads/Apps/Scraper
source .venv/bin/activate
python3 supportal_nicegui_app.py

Open localhost:8765
2
Start Chainlit (optional chat UI)
In a second terminal:
source .venv/bin/activate
chainlit run chainlit_app.py --port 8766

Open localhost:8766
3
Create a Profile
In NiceGUI → Configuration tab:

  • Set Couchbase URL, bucket, username & password
  • Click Test Connection to verify
  • Choose LLM provider (Claude / Gemini / Ollama / LMStudio)
  • Choose embedding provider + model + dimensions
  • Save profile — settings apply to both UIs
4
Create FTS Index
Still in Configuration:

  • Click Create / Update FTS Index
  • Builds hybrid BM25 + vector index on the transcripts scope
  • Only needed once, or after changing embedding dimensions
  • Index name: supportal_hybrid
profile saved → ready to authenticate
2
Authenticate with Supportal — refresh when cookie expires (~8 h)
Choose whichever method you have available
Option A — Paste Cookie (recommended)
Copy from Browser DevTools
1. Log into supportal.couchbase.com in your browser
2. Open DevTools → Application → Cookies
3. Copy the full Cookie header value
4. Paste into the Cookie field in NiceGUI Configuration tab
5. Click Save Cookie — all scraping runs headless
OR
Option B — Browser SSO Login
Let Playwright log in for you
1. Click Login with Browser in Configuration tab
2. A Chromium window opens — complete the SSO flow
3. Cookie is extracted automatically and saved to the profile
4. Chromium closes — all subsequent scraping is headless
5. Re-run on 403 errors or session expiry
cookie active → ready to ingest data
3
Ingest Data — per customer, run periodically or via agent
Pull tickets and cluster snapshots from Supportal into Couchbase
A
Scrape Tickets
NiceGUI → Scraping tab:

  • Enter customer org name (or alias)
  • Click Scrape Tickets
  • Change-detection skips unchanged tickets on re-runs
  • Results stored in transcripts.tickets

Or via agent: "Scrape latest tickets for Acme Corp"
scrape_customer_tickets
B
Fetch Snapshot Stubs
NiceGUI → Scraping tab → Snapshots section:

  • Click Fetch Snapshot Stubs
  • Uses POST /api/support360/query — one round-trip for all snapshot IDs
  • Stubs saved to transcripts.snapshots (no topology yet)

Or via agent: "Fetch snapshot stubs for Acme"
fetch_snapshots
C
Backfill Topology
NiceGUI → Scraping tab → click Backfill Topology:

  • Fetches GET /snapshot/{enc}/nutshell per stub
  • Parallel workers — configurable in settings
  • Adds: CB version, node layout, services, bad/warn items
  • Skips stubs already fully populated

Or via agent: "Backfill topology for pending snapshots"
backfill_snapshot_topology
D
Embed Tickets
NiceGUI → Scoring & Analysis tab:

  • Click Embed All Tickets (or new tickets only)
  • Generates 1024-dim vectors via configured embedding model
  • Vectors stored in transcripts.tickets alongside text
  • Required for vector_search to work in chat
data in Couchbase → ready to analyze
4
Analyze & Query
Use either UI — same agent tools, same Couchbase data
NiceGUI Chat tab — localhost:8765
🖥 Quick queries & admin operations
  • Go to Chat tab
  • Type your question in natural language
  • Agent calls tools automatically (up to 5 turns)
  • Charts rendered inline with ECharts
  • Tables downloadable as CSV / Excel
  • Good for: scoring runs, bulk re-scrapes, preflight checks
OR
Chainlit Chat — localhost:8766
💬 Deep research & thread history
  • Login (any username & password)
  • Set customer scope in sidebar settings
  • Browse prior sessions in thread sidebar
  • Same 17-tool agent — full parity with NiceGUI
  • Charts via Plotly; assets persisted and restored on resume
  • Good for: multi-session research, saving findings, sharing

💡
Tips & Shortcuts
Patterns that save time in day-to-day use
Cookie expiry Supportal sessions last ~8 hours. If scraping returns 403 errors or the agent reports empty results, your cookie has expired. Re-paste or re-run browser login.
Incremental scraping Re-running scrape_customer_tickets is safe — change-detection skips tickets whose content hasn't changed. Only new or updated tickets are written to Couchbase.
Embedding after ingest New tickets won't appear in semantic / vector search until embedded. Run Embed Tickets in the Scoring tab after any scrape, or embed as part of your ingest routine.
Snapshot two-step Stub fetch is fast (one Analytics API call). Topology backfill is slow (one REST call per snapshot). Run the stub fetch first to see what's available, then backfill overnight or in the background.
Agent data routing The agent automatically chooses LOCAL (Couchbase) vs LIVE (Supportal API) based on your question. Ask explicitly if needed: "using live data, show me…" or "from our local copy, …"
Chainlit thread resume Prior sessions appear in the sidebar. Click any thread to resume — charts and tables are restored from chat.assets. Threads are scoped per login user.
Results tab export The NiceGUI Results tab provides quick CSV / Excel export without needing to ask the agent. Use it for bulk extracts; use the agent for analysis and visualisation.
Local LLM quirks Ollama / LMStudio models may hallucinate tool argument names. The app tolerates ticket_ids (plural list) in place of ticket_id for rescrape calls automatically.
Profile = shared config The active NiceGUI profile drives the Chainlit app too — LLM provider, embedding model, CB connection, and cookie are all read from the same saved profile. Change once, applies everywhere.
