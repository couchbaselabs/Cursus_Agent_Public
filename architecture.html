Supportal AI Agent — Application Architecture

Two-UI AI platform for Couchbase support ticket analysis · REST API scraping, embedding, agent tooling, and chat history

🌐 Supportal / Zendesk supportal.couchbase.com
Ticket REST endpoints
  • GET /customer/{org}/status/tickets — listing
  • GET /zendesk/ticket/{id}/status — detail
  • Comments, tags, priority, status, CBSE IDs
Analytics API
  • POST /api/support360/query
  • SQL++ against snapshot, cluster, customer
  • Fast bulk snapshot listing with ticket IDs
  • Live fleet-wide counts & version stats
Snapshot REST endpoints
  • GET /customer/{org}/status/snapshots — listing
  • GET /snapshot/{enc}/nutshell — topology (primary)
  • GET /api/snapshots/{enc}/nutshell/summary — fallback
  • CB version, RAM, node services, bad/warn items
Auth modes
  • Cookie paste → all REST calls headless
  • Browser SSO login (headful Playwright — session cookie only)
  • Re-authenticate on 403 / session expiry
REST API scraping (tickets, snapshots, topology)
direct HTTP (analytics API — agent tools)
🔌 REST API Scraping Layer
Ticket ingestion
  • Fetch ticket listing via /customer/{org}/status/tickets
  • Resolve canonical org slug via redirect before listing call
  • Fetch full ticket detail via /zendesk/ticket/{id}/status
  • Change-detection — skip unchanged tickets on incremental runs
Snapshot ingestion — two-step
  • Step 1 — Analytics stub fetch (fast): POST /api/support360/query SQL++ returns all snapshot IDs + ticket associations in one round-trip
  • Step 2 — Topology backfill: per-stub GET /snapshot/{enc}/nutshell fetches CB version, node layout, services, bad/warn items; parallel workers configurable
Session — Playwright (SSO login only)
  • Cookie paste → all scraping runs headless via requests
  • SSO required → headful Chromium launched once → cookie extracted & saved to .playwright_supportal/
  • Playwright not used for data scraping — REST API only

💬 Chainlit Chat localhost:8766
Interface
  • Password-authenticated login (any username, any password)
  • Thread sidebar — browse & resume prior sessions
  • Thread named from first user message + customer prefix
  • Settings panel — customer scope, LLM provider, model override
AI agent
  • Same tool suite as NiceGUI (LOCAL + LIVE + OUTPUT)
  • Tool-calling loop up to 5 turns per message
  • DATA SOURCE ROUTING — local vs Supportal based on query intent
  • SCOPING RULE — customer-scoped with discovery exceptions
Persistence
  • Charts → Plotly inline; stored as base64 JSON in chat.assets
  • Tables → Dataframe inline; also stored in chat.assets, tagged with originating prompt
  • Assets restored on thread resume
  • Conversation log shared with NiceGUI via chat.history
Custom data layer
  • CouchbaseDataLayer — full Chainlit BaseDataLayer implementation
  • Auto-creates chat scope + collections + primary indexes on first run
  • Connection loaded from active NiceGUI profile (no separate config)
↔ Shared conversation history (chat.history) — write from either UI, read from both
