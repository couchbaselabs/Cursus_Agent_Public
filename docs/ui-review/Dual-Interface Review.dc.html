01 — The short version

What we found, in one breath

Strabo and Corax are two well-built apps that solve overlapping jobs with different tools. Both run the same agent, both draw the same charts, both read the same tickets — but they look different, behave differently, and force the engineer to guess which door to walk through. The data is unified; the experience is not.

2×
chat + charting surfaces for the same agent — Strabo's Chat tab and all of Corax.
18+
tabs & sub-tabs in Strabo alone — deep, dense, hard to teach and hard to demo.
2
visual languages — NiceGUI blue/Material vs. Chainlit chat — with no shared identity.
1
product it should feel like: a dashboard you manage data in, with the agent one panel away.
The overlap is the risk

When two apps do the agent job, both must be maintained, both drift, and neither becomes the obvious home. Consolidate the agent into one embedded surface.

Density hides the value

Strabo's 7 tabs × deep sub-tabs bury the two things leadership cares about: fleet health and customer-ready reports. Lead with outcomes, not configuration.

Reporting & automation = one home

Assets, generated reports, scrape jobs and freshness checks are scattered. Unify them into a single "Reports & Automation" space the assistant can drive.

04 — The four tensions

What keeps showing up

1 · Overlap — two agents, two chart engines

Strabo's Chat tab and all of Corax run the same 40+ tools and draw the same ECharts. Every new capability must be built, tested, and styled twice.

→ One assistant, embedded once. Retire the duplicate surface.
2 · Density — no obvious front door

7 top tabs, ~18 sub-tabs, config-first landing. A new AE or a leader can't tell where value lives in the first 30 seconds.

→ Land on fleet health. Push config to a settings corner.
3 · Identity — two visual languages

NiceGUI blue/Material vs. Chainlit's chat theme. No shared type, color, spacing, or Couchbase brand. They read as two products from two teams.

→ One design system: type, color, chart palette, components.
4 · Fragmented outputs — reporting & automation scattered

Reports, assets, scrape jobs and freshness checks live across tabs and both apps. There's no single place to see "what was produced" and "what's running."

→ A Reports & Automation hub the assistant can drive.
05 — Recommended direction

One product: dashboard-first,
assistant one panel away.

Keep the dashboard's structure and Strabo's data-management strengths. Collapse Corax into a persistent, dockable assistant panel that shares the app's customer scope, history, and chart style. You manage and read in the main canvas; you ask and generate in the panel — and everything the agent makes lands in the same Reports hub.

07 — How to get there

A staged, low-risk path

STEP 1 · ALIGN
One look

Shared type, color, Couchbase brand and one chart palette across both apps. Cheapest win; makes them feel like siblings today.

STEP 2 · LAND
Fleet-first entry

Make "Fleet at a glance" the Strabo landing screen; demote Configuration to a corner. Answers "where's the value?" instantly.

STEP 3 · MERGE
Embed the assistant

Dock Corax as a panel sharing scope & history; retire Strabo's Chat tab. One agent surface, threads intact.

STEP 4 · UNIFY
Reports & Automation hub

Fold Assets + reports + jobs + freshness into one hub the assistant drives. Delivers the "one place for reporting & automation" goal.
