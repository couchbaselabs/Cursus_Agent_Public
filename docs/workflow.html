Supportal AI Agent — User Workflow v2.4.9

Step-by-step guide: setup → authentication → data ingestion → analysis

1
Initial Setup — one time
Start both servers and configure your connection profile
🖥 Start NiceGUI
cd ~/Downloads/Apps/Scraper
source venv/bin/activate
python run_nicegui.py
  • Opens at localhost:8080
💬 Start Chainlit (optional)
source venv/bin/activate
python run_chainlit.py
  • Opens at localhost:8766
⚙️ Create a Profile
  • NiceGUI → Configuration tab
  • Set Couchbase URL, bucket, username & password
  • Click Test Connection to verify
  • Choose LLM provider (Claude / Ollama / LMStudio)
  • Choose embedding provider + model + dimensions
  • Save profile — applies to both UIs
🔍 Create FTS Index
  • Still in Configuration
  • Click Create / Update FTS Index
  • Builds hybrid BM25 + vector index on the supportal scope
  • Only needed once, or after changing embedding dimensions
  • Index name: supportal_hybrid
✓ profile saved → ready to authenticate
2
Authenticate with Supportal — refresh when cookie expires (~8 h)
Choose whichever method you have available
🍪 Option A — Paste Cookie (recommended)
  • Log into supportal.couchbase.com in your browser
  • Open DevTools → Application → Cookies
  • Copy the full Cookie header value
  • Paste into the Cookie field in NiceGUI Configuration
  • Click Save Cookie — all scraping runs headless
🌐 Option B — Browser SSO Login
  • Click Login with Browser in Configuration tab
  • A Chromium window opens — complete the SSO flow
  • Cookie is extracted automatically and saved to profile
  • Chromium closes — all subsequent scraping is headless
  • Re-run on 403 errors or session expiry
✓ cookie active → ready to ingest data
3
Ingest Data — per customer, run periodically or via agent
Pull tickets and cluster snapshots from Supportal into Couchbase
🎫 Scrape Tickets
  • NiceGUI → Scraping tab
  • Enter customer org name (or alias)
  • Click Scrape Tickets
  • Change-detection skips unchanged tickets on re-runs
  • Reconcile step removes deleted Zendesk tickets from CB
  • Results stored in supportal.tickets
  • Or via agent: "Scrape latest tickets for Acme Corp"
scrape_customer_tickets
📸 Fetch Snapshot Stubs
  • NiceGUI → Scraping tab → Snapshots section
  • Click Fetch Snapshot Stubs
  • Uses POST /api/support360/query — one round-trip
  • Stubs saved to supportal.snapshots (no topology yet)
  • Or via agent: "Fetch snapshot stubs for Acme"
fetch_snapshots
🔬 Backfill Topology
  • NiceGUI → Scraping tab → click Backfill Topology
  • Fetches GET /snapshot/{enc}/nutshell per stub
  • Adds: CB version, node layout, services, bad/warn items
  • RAM/node, CPUs/node, GSI/FTS/Eventing counts
  • Skips stubs already fully populated
  • Or: "Backfill topology for pending snapshots"
backfill_snapshot_topology sync_snapshots
🧠 Embed Tickets
  • NiceGUI → Scoring & Analysis tab
  • Click Embed All Tickets (or new tickets only)
  • Generates vectors via configured embedding model
  • Vectors stored in supportal.tickets alongside text
  • Required for vector_search to work in chat
✓ data in Couchbase → ready to analyze
4
Analyze & Query
Use either UI — full agent parity, different strengths
🖥 NiceGUI Chat — localhost:8080
  • Quick queries, admin ops, pipeline control
  • Inline ECharts (12 types, SVG/PNG export)
  • Assets tab — browse saved charts, CSVs, reports
  • Analytics tab — drill-down charts with click handlers
  • Customers tab — health scores + P1 count badges
  • Good for: day-to-day triage, dashboard review
💬 Chainlit Chat — localhost:8766
  • Threaded sessions with full history sidebar
  • Live tool status updates per agent turn
  • Job monitors survive tab close + reconnect
  • Assets restored on session resume from CB
  • Mobile-friendly layout
  • Good for: multi-session research, sharing findings

Chainlit — interactive triggers
🚀 Chat Starters (shown before first message)
  • Morning Briefing → calls get_portfolio_status — fleet-wide urgency rank
  • What's New? → asks for 24 h digest for the current customer
  • Open P1 Tickets → queries all open P1s
  • Customer Health Dashboard → get_customer_health_score summary
⚡ Quick Actions bar (sent after chat start / settings save)
  • ☀ Morning Briefing → get_portfolio_status — always visible
  • 📊 Quick Dashboard → portfolio health score summary — always visible
  • 🆕 What's New? (Customer) → 24 h digest — only shown when a customer is set
  • 🔖 Saved Queries → browse + re-run CB-persisted queries — only when customer is set
  • 📚 Prompt Library → two-step category browser (see below) — always visible
📚 Prompt Library flow (supportal/prompt_library.py — 28 prompts, 7 categories)
  • Click 📚 Prompt Library → shows 7 category buttons (Morning Routine, Health & SLA, Fleet Analysis, Ticket Investigation, Cluster & Snapshot, Data Freshness, Reporting)
  • Select a category → shows up to 5 prompt buttons for that category; customer_required prompts are hidden when no customer is set
  • Click a prompt → {customer} placeholder is substituted with the active customer name, then sent through the full agent loop
  • ← Back button returns to the category list without re-sending a message
  • NiceGUI equivalent: nested expansion panels under Prompt Library in the sidebar
🔄 Post-response actions (appear after each agent reply)
  • Retry → re-sends the same message if the agent errored
  • Follow-up chips → AI-generated suggestions (up to 3) based on Q&A context
🔖 Saved Queries flow
  • Click Saved Queries → lists CB-persisted queries for current customer
  • Each query gets a ▶ Run action button
  • Clicking Run re-executes the query through the full agent loop
  • Save a new query via agent: "Save this query for next time" → save_query
Tips & Shortcuts
Cookie expiry

Supportal sessions last ~8 hours. If scraping returns 403 errors or the agent reports empty results, your cookie has expired. Re-paste or re-run browser login.

Incremental scraping

Re-running scrape_customer_tickets is safe — change-detection skips tickets whose content hasn't changed. Deleted Zendesk tickets are automatically removed from CB (reconcile step).

Embedding after ingest

New tickets won't appear in semantic search until embedded. Run Embed Tickets in the Scoring tab after any scrape, or ask the agent to embed as part of the ingest.

Snapshot two-step

Stub fetch is fast (one Analytics API call). Topology backfill is slow (one REST call per snapshot). Run stub fetch first to see what's available, then backfill in background. Or use sync_snapshots to do both in one agent call.

Agent data routing

The agent automatically chooses LOCAL (Couchbase) vs LIVE (Supportal API) based on your question. Ask explicitly if needed: "using live data, show me…" or "from our local copy, …"

Chainlit thread resume

Prior sessions appear in the sidebar. Click any thread to resume — charts and tables are restored from chat.assets. Job monitors re-attach automatically on reconnect.

Results tab export

The NiceGUI Results tab provides quick CSV / Excel export without asking the agent. Use it for bulk extracts; use the agent for analysis and visualisation.

Profile = shared config

The active NiceGUI profile drives the Chainlit app too — LLM provider, embedding model, CB connection, and cookie are all read from the same saved profile. Change once, applies everywhere.

MCP server

Run python apps/mcp/server.py and add it to Claude Desktop's mcp_servers config to use all 29 agent tools directly from the Claude desktop app.
